# Arvan Photos 📸

یک اپلیکیشن گالری و بک‌آپ عکس با Flutter، به‌عنوان یک تمرین مهندسی که به‌طور دقیق از **Google Photos** الگو گرفته: مرور گالری دستگاه گروه‌بندی‌شده بر اساس تاریخ، بک‌آپ اختیاری (opt-in)، وضعیت زنده‌ی آپلود هر عکس، و سینک در پس‌زمینه — با استفاده از **ArvanCloud Object Storage** (سازگار با S3) به‌جای زیرساخت گوگل.

این README **وضعیت واقعی و تأییدشده‌ی فعلی پروژه** رو نشون می‌ده (بر اساس بررسی مستقیم کد، نه چیزی که قرار بوده باشه) — هر قابلیتی که پایین اومده یا کار می‌کنه، یا عمداً خارج از اسکوپه، یا صریحاً به‌عنوان مشکل شناخته‌شده علامت خورده. هیچ‌چیز اینجا آرزویی/فرضی نیست.

## 🎯 این اپ واقعاً چیکار می‌کنه

اپ دو تب مستقل داره، هرکدوم با منبع داده و BLoC جدا:

| تب | منبع داده | وضعیت |
|---|---|---|
| **Photos** | گالری دستگاه (`photo_manager`) | کاملاً فعال — گروه‌بندی تاریخ، انتخاب تکی/گروهی/همه، بک‌آپ دستی + خودکار اختیاری، وضعیت زنده‌ی آپلود |
| **Cloud** | ArvanCloud (لیست S3) | لیست + اسکرول بی‌نهایت کاملاً فعال؛ **فقط نمایشی** (به بخش محدودیت‌ها نگاه کن) |

تب‌های `Library`، `Create` و `Search` عمداً استاب‌اند (حالت خالی، «به‌زودی») — این از اول یک تصمیم آگاهانه‌ی اسکوپ بوده، نه سهل‌انگاری.

### تب Photos، با جزئیات
- عکس‌های دستگاه گروه‌بندی‌شده بر اساس تاریخ (امروز/دیروز/تاریخ)، تأییدشده که کار می‌کنه
- انتخاب: عکس تکی، کل یک گروه تاریخ (با تپ روی هدر گروه)، یا Select All
- **بک‌آپ دستی:** هرچی انتخاب کنی، دکمه‌ی Back Up رو بزن
- **بک‌آپ خودکار (اختیاری، پیش‌فرض خاموش):** یک toggle در تنظیمات بک‌آپ، متکی به `SharedPreferences`. وقتی روشنه، `DeviceGalleryBloc` در هر اجرا عکس‌های جدید بک‌آپ‌نشده رو تشخیص و enqueue می‌کنه
- **آپلود در پس‌زمینه:** `flutter_background_service` یک Foreground Service اجرا می‌کنه که صف آپلود رو (حداکثر ۵ همزمان) حتی بعد از بسته‌شدن اپ پردازش می‌کنه
- **نوتیفیکیشن زنده:** پیشرفت به همراه دکمه‌های Pause/Resume/Stop، از طریق `flutter_local_notifications`
- **حذف از ابر:** حذف یک عکس سینک‌شده از گالری دستگاه، از ArvanCloud هم حذفش می‌کنه

### تب Cloud، با جزئیات
- هرچی الان در باکت ArvanCloud ذخیره شده رو با اسکرول بی‌نهایت (بر اساس `continuationToken`) لیست می‌کنه
- **فقط نمایشی** — طبق تصمیم محصول، حذف و ویرایش از این تب در دسترس نیست (این‌ها برای آیتم‌های سینک‌شده از تب Photos در دسترسن)

## 🏗️ معماری

**Clean Architecture**، ساختار Feature-first، سه لایه در هر فیچر (`data` / `domain` / `presentation`)، یک قانون وابستگی: وابستگی‌ها فقط رو به داخل.

```
presentation  ──وابسته به──>  domain  <──وابسته به── data
```

```
lib/
├── core/                  # DI، شبکه (S3 SigV4)، دیتابیس، تم
├── features/
│   ├── cloud/              # نمایش لیست ArvanCloud (data/domain/presentation)
│   └── photos/              # گالری دستگاه + موتور بک‌آپ (data/domain/presentation)
└── main.dart
```

> **انحراف شناخته‌شده از طرح اولیه:** `features/photos` به‌طور محسوسی از `features/cloud` بزرگ‌تر شده، چون هم مرور گالری هم کل موتور بک‌آپ (صف، سرویس پس‌زمینه، نوتیفیکیشن) رو نگه می‌داره. جدا کردن بک‌آپ به یک ماژول فیچر مستقل، یک ریفکتور منطقی برای آینده است.

### SOLID و Design Pattern‌ها — وضعیت صادقانه

| اصل/پترن | وضعیت |
|---|---|
| قانون وابستگی (presentation → domain ← data) | در اکثر کد رعایت شده |
| Repository Pattern | برای هر دو فیچر کامل پیاده‌سازی شده |
| UseCase Pattern | برای اکثر عملیات‌ها (Enqueue, Delete, Get) پیاده شده؛ چند مسیر هنوز مستقیم از Bloc به Data Source وصل‌ان (نقض شناخته‌شده، پایین‌تر ببین) |
| Dependency Injection | کاملاً با `get_it` + `injectable` مدیریت می‌شه |
| **نقض‌های شناخته‌شده:** | منطق گروه‌بندی تاریخ الان داخل `DeviceGalleryBloc` هست، نه یک UseCase در domain. `AppBackgroundService` مستقیم با دیتابیس محلی کار می‌کنه، از لایه‌ی repository رد می‌شه — یک trade-off عملی چون توی یک Isolate جدا در پس‌زمینه اجرا می‌شه، ولی بازم نقض لایه‌بندیه که اگه پرسیدن باید بتونی توضیحش بدی |

### چرا S3 Client دستی به‌جای SDK آماده
S3 Client مستقیم روی `dio` + `aws_signature_v4` + parse دستی XML ساخته شده، نه با یک SDK کامل S3. Trade-off: کد بیشتری برای نگه‌داری، ولی دید کامل روی این‌که دقیقاً چی امضا و ارسال می‌شه — که موقع دیباگ رفتارهای خاص ArvanCloud (مثل `204 No Content` روی حذف، که پیاده‌سازی‌های ساده‌لوح گاهی فقط با چک کردن `200` اشتباه مدیریتش می‌کنن) خیلی به کار اومد.

## 🛠️ Tech Stack

| دسته | ابزار |
|---|---|
| فریمورک | Flutter (SDK ^3.12.2)، Dart |
| مدیریت وضعیت | `flutter_bloc` (^8.1.4) |
| Dependency Injection | `get_it`، `injectable` |
| ذخیره‌سازی ابری | `aws_common`، `aws_signature_v4`، `dio` (S3 Client دستی) |
| ذخیره‌سازی محلی | `sqflite` (صف بک‌آپ + وضعیت سینک) |
| گالری دستگاه | `photo_manager`، `photo_manager_image_provider` |
| اجرای پس‌زمینه | `flutter_background_service`، `flutter_local_notifications` |
| ویرایش عکس | `image_cropper` (UseCase پیاده شده، **هنوز به هیچ دکمه‌ای در UI وصل نیست** — به محدودیت‌ها ببین) |
| مدیریت خطا | `dartz` (`Either<Failure, T>`) — به‌طور یکدست در فیچر Photos استفاده شده |
| تست | `bloc_test`، `mocktail` |

## ⚙️ راه‌اندازی

### پیش‌نیازها
- Flutter SDK ^3.12.2
- یک باکت ArvanCloud Object Storage با دسترسی **Public Read**
- یک Machine User (Access Key / Secret Key)، ترجیحاً محدود به همین باکت

### نصب
```bash
git clone <repository-url>
cd arvan_photos
flutter pub get
```

### متغیرهای محیطی
فایل `assets/env` بساز (در `.gitignore`، هرگز کلید واقعی کامیت نشه):
```env
ARVAN_ACCESS_KEY=your_access_key
ARVAN_SECRET_KEY=your_secret_key
ARVAN_BUCKET=your_bucket_name
ARVAN_ENDPOINT=https://your-bucket.s3.ir-thr-at1.arvanstorage.ir
ARVAN_REGION=ir-thr-at1
```

### تولید کد
```bash
dart run build_runner build --delete-conflicting-outputs
```

### اجرا
```bash
flutter run
```

## ⚠️ محدودیت‌های شناخته‌شده

بعضی از این‌ها تصمیم آگاهانه‌ی اسکوپ‌ان؛ دوتاشون واقعاً باگ‌ان. عمداً از هم جدا نگه داشته شدن:

**تصمیمات آگاهانه‌ی اسکوپ:**
- **بدون حذف/ویرایش از تب Cloud.** تب Cloud عمداً فقط نمایشیه؛ حذف فقط از تب Photos برای آیتم‌های سینک‌شده در دسترسه.
- **بدون حذف از دستگاه.** فقط حذف از کلود پیاده شده؛ پاک‌کردن عکس از خود گالری دستگاه خارج از اسکوپه.
- **تشخیص خودکار عکس‌های جدید در پس‌زمینه محدوده.** `photo_manager` موقع اجرا داخل یک Isolate پس‌زمینه محدودیت داره، برای همین سرویس پس‌زمینه فقط آیتم‌هایی که *از قبل* در صف‌ان رو پردازش می‌کنه — خودش گالری دستگاه رو برای عکس کاملاً جدید، وقتی اپ کاملاً بسته‌ست، اسکن نمی‌کنه. تشخیص عکس جدید وقتی اپ باز می‌شه (foreground) اتفاق می‌افته، نه صرفاً در پس‌زمینه.
- **iOS تست نشده و صریحاً پشتیبانی نمی‌شه** (`ios: false` در تنظیمات پلتفرم) — این پروژه طبق طراحی فقط اندرویده.
- **چیدمان‌های «Comfortable»/«Month»، «Stack similar photos» و «Show shimmer»** در تنظیمات Photos View، عمداً استاب ظاهری‌ان (نیازمند ML روی دستگاه، خارج از اسکوپ).

**باگ‌های واقعی (هنوز رفع نشده):**
- `EditPhotoUseCase` (کراپ/چرخش) کامل پیاده‌سازی شده ولی **هیچ نقطه‌ورودی UI نداره** — الان هیچ دکمه‌ای جایی صداش نمی‌زنه.
- دو تست واحد الان فیل می‌شن (بخش تست بالا رو ببین).
